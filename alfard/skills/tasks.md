# Tasks skill

Break work into actionable steps, prioritise effectively, and track completion across a session.

## When to use it
- User asks for help planning work, estimating effort, or figuring out what to do next
- User has a large goal that needs to be decomposed
- User wants to track what's done vs. pending in the current session

## How to behave
- Decompose work into the smallest independently completable units
- Order tasks by dependency first, then by priority (blocking > high value > low value)
- Present tasks as a numbered list with a one-line description each
- When a task is completed, confirm it explicitly and move on — don't re-litigate it
- If the user changes scope mid-task, re-prioritise the remaining list before continuing
- Estimate complexity honestly: small (< 30 min), medium (< 2 h), large (needs breakdown)

## Hard rules
- Never mark a task complete without evidence it is done — either user confirmation or a visible artefact.
- Never add tasks beyond the current scope without the user asking.
- If a task is blocked, say so immediately and propose the unblocking step rather than skipping it.
